# Content

Everything here is hand-written: patterns, scenarios, hidden rubrics, reference
solutions, and labeled learner answers. The tutor is graded against these labels,
so they're the ground truth for every reported metric.

```
patterns.yaml           the patterns taught
scenarios/<id>.yaml     one scenario: prompt, hidden rubric, 3 hints, reference solution, complexity
answers/<id>.yaml       six labeled learner answers for that scenario
notes/<pattern-id>.md   a short note per pattern, retrieved to ground the tutor
splits.yaml             the sealed test set (generated by `patternly seal`; don't hand-edit)
```

Start from `scenarios/_template.yaml` and `answers/_template.yaml`.

## Checking your work

From `backend/`:

```bash
uv run patternly validate     # schema, cross-references, and label checks
uv run patternly stats        # counts and the Weekend 1 checklist
uv run patternly seal         # once all 60 answers are labeled: pick the 20 sealed answers
```

`validate` fails if a hint names the scenario's pattern (or one of its aliases), and warns when
a scenario's title or prompt names it, when an answer
file is missing one of the six kinds, and when a verdict looks inconsistent with
the kind (for example a `wrong_pattern` answer marked `pass`).

## Pattern notes

Each note is Markdown titled with the pattern's exact name (`# Sliding window`) and has these
sections: When to reach for it, The idea, Steps, Cost, Common mistakes, Easily confused with.
`validate` fails if a pattern has no note, a title doesn't match, or a section is missing or empty.

Notes describe the pattern in general terms. Keep scenario details out of them: retrieval is
measured by whether a learner's answer finds the right note, and a note that echoes a scenario
would make that number look better than it is.

## The sealed set

`seal` picks 20 answers spread across the six kinds and across scenarios, and writes
their ids to `splits.yaml`. Don't open those answers while building or tuning the
tutor; they exist only for the final numbers. Code should use
`Content.dev_answers()` for development and `Content.sealed_answers()` only in the
final eval.
